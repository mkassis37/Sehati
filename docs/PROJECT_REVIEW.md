# تقرير مراجعة صحتي الأولي

**الفرع:** `feature/android-foundation-plus`  
**نطاق المراجعة:** الشاشات، نماذج Room والترحيلات، تشفير قاعدة البيانات والمرفقات والنسخ الاحتياطي، استيراد PDF/OCR، إعدادات التطبيق، ملفات البناء وCI.  
**الحالة:** مراجعة ساكنة واختبارات بناء ووحدة وLint على نسخة التطوير؛ فحص المحاكي وPDF واستعادة النسخة النظيفة ما تزال غير مكتملة، لذلك لا يعد هذا التقرير إثباتًا لاكتمال الوظائف أو الأمان.

## الوظائف الموجودة

- تطبيق Android أصلي بـ Kotlin وJetpack Compose، وواجهة عربية RTL وسمة لونية فاتحة/داكنة.
- ملفات متعددة لأفراد العائلة مع إنشاء وعرض وتعديل، وقراءة منفصلة للحساسيات والأدوية والنتائج والوثائق بحسب `memberId`.
- الحساسية: إضافة وعرض وحذف؛ تشمل التصنيف والمادة والأعراض والشدة والملاحظات، مع حقلي الاسم التجاري والمادة الفعالة لحساسية الدواء.
- المختبر: إدخال يدوي للنتائج الرقمية، وقيم وحدات ومجالات مرجعية وتاريخ ومختبر، وتصفية حسب الفحص والوحدة، ومقارنة ورسم خطي بسيط.
- استيراد PDF: عرض الصفحات واستخراج نص محلي عبر PDFBox أو OCR محلي، ثم اقتراح النتائج الرقمية ومراجعتها يدويًا قبل الحفظ.
- المرفقات: PDF وصور JPG/PNG/WebP تحفظ مشفرة محليًا بمفتاح Android Keystore وبحد إدخال 25 MB؛ يمكن ربطها بإجراء طبي وفتحها عبر FileProvider.
- الأدوية: إنشاء وتعديل وحذف حقول الدواء والجرعة والفترة والطبيب والتعليمات؛ يوجد مفتاح حالة نشط/متوقف.
- قفل PIN اختياري، وتحقق حيوي عند توفره، وSQLCipher مع مفتاح ملفوف بـ AES-GCM في Android Keystore.
- تصدير واستعادة نسخة مشفرة بكلمة مرور مستقلة، تشمل الأفراد والحساسية والنتائج والأدوية والوثائق وبيانات الملف الصحي الجديدة. صيغة v2 تقبل أيضًا نسخ v1 القديمة.
- CI يتضمن مهام بناء واختبارات وحدة وLint، ورفع APK تجريبي عند نجاحها. إصدار Release يتطلب أسرار توقيع غير موجودة في المشروع.

## وظائف ناقصة أو شكلية حاليًا

- المواعيد والزيارات المستقلة والتقارير الطبية القابلة للتصدير ما زالت شاشات مستقبلية.
- جدول الأدوية يخزن أوقاتًا ونص التكرار، لكن لا يوجد جدولة تنبيهات أو تسجيل جرعة مأخوذة/فائتة أو تنبيه انتهاء العلاج.
- المختبر لا يدعم النتيجة النوعية مثل `Nil` و`Hazy`؛ النموذج الحالي يقبل `Double` فقط. لا يوجد إنشاء تقرير PDF.
- لا يوجد ربط Google Drive أو نسخ تلقائي يومي أو سجل لآخر نسخة. الموجود تصدير واستعادة يدويان بملف يختاره المستخدم.
- اختبارات Room على Android أضيفت، لكن لم تُشغّل بعد لعدم توفر محاكي قادر على الإقلاع. لا توجد حتى الآن اختبارات كاملة للاستعادة والمرفقات على تثبيت نظيف.

## قاعدة البيانات والخصوصية

- Room على SQLCipher، الإصدار 7، مع ترحيلات 1→7. يضيف الترحيل 6→7 حقول الملف وبطاقة الطوارئ وخمسة جداول مفهرسة وسلسلة المرفق بالإجراء دون مسح البيانات. لا توجد في الكيانات علاقات FK أو CASCADE، لذلك تعتمد إزالة البيانات التابعة على معاملة صريحة.
- النسخ التلقائي لـ Android مستبعد في manifest وقواعد استخراج البيانات؛ وتخزين مفتاح قاعدة البيانات في `noBackupFilesDir`.
- الوثائق تُشفّر AES-GCM بمفتاح Android Keystore. نسخة مؤقتة من PDF/الصورة تُفك في cache لفتحها عبر تطبيق آخر ثم تنظف عند الحذف أو بدء التطبيق التالي.
- نسخة التصدير نفسها مشفرة AES-GCM مع اشتقاق PBKDF2؛ الاستعادة تستبدل السجلات الحالية بعد معاينة وتأكيد واضحين.
- لا يوجد مزود مزامنة سحابي أو Google Drive مُعد. التحديث Release يتطلب اتصالًا بـ GitHub، أما السجلات فتظل محلية.
- لا تزال سلامة Keystore وفتح المرفقات، فشل الاستعادة، وحدود الذاكرة بحاجة إلى تحقق على جهاز. جمع الصفوف للنسخ أصبح داخل معاملة قراءة متسقة.

## ترتيب العمل المقترح

1. تشغيل اختبارات Android المضافة على محاكي أو جهاز حقيقي والتحقق بصريًا من الواجهات ومورد البداية.
2. اختبار نسخة v1 واستعادة v2 على تثبيت نظيف، بما يشمل المرفقات المرتبطة بالإجراءات وسيناريو فشل الكتابة.
3. تجربة OCR للملف الممسوح، مع تحقق يدوي دون حفظ القيم تلقائيًا؛ استكمال اختبار الصور وPDF المشفر.
4. تنفيذ المواعيد والتقارير الطبية والجرعات والتنبيهات. Google Drive يتطلب تدفق OAuth وموافقة على سلوك المزامنة والخصوصية.

## فحوص لم تُنفذ بعد

- تم تشغيل `assembleDebug` و`testDebugUnitTest` و`lintDebug` و`assembleDebugAndroidTest` بنجاح. اختبارات الوحدة الخمسة بلا فشل. جُمّع اختبارا Android لقاعدة البيانات والترحيل لكن لم ينفذا على جهاز. تظهر تحذيرات API قديم وإصدارات تبعيات أحدث وتحذير metrics في إعداد Android SDK.
- تشغيل Android instrumentation tests للتحقق من فصل الأفراد وحذف التوابع والترحيل فعليًا.
- استعادة نسخة v1/v2 ومرفقات PDF/الصور على تثبيت نظيف.
- تعذر تشغيل AVD على هذه الآلة لأن Windows Hypervisor Platform غير متاح للمحاكي (`x86_64 emulation currently requires hardware acceleration`). لم تثبت نسخة التطبيق ولم تنفذ اختبارات Android أو فحص واجهة حقيقي.
- تجربة OCR للصفحات الست ومقارنة المرشحات مع التقرير الأصلي. الملف المرفق ممسوح ضوئيًا ولا يحتوي طبقة نص؛ يحتاج OCR على جهاز Android، ولم تتم قراءة نتائجه الطبية أو حفظها.
- التحقق بصريًا من شاشة البداية والأيقونة داخل APK على المحاكي. بصمات الملفات الأصلية لم تتغير: splash `B29D41C746C7937BE20C3A65469859A6B61D98959A58AA7B2A9DA4A72D28EF9A`، والأيقونة `7657DF2081AEC081B54A2C1EAEEB0218F978F11EF43B02D17FB3DF332C677C5E`.
- إنشاء artifact عبر GitHub Actions لكل commit تطوير ناجح. لا Release رسمي ضمن هذه المرحلة.

## عوائق ومتطلبات قبل إصدار تجريبي موثوق

- المحاكي يحتاج تفعيل/إتاحة تسريع المحاكاة من Windows أو جهاز Android فعلي. البناء على JVM لا يثبت سلوك SQLCipher وKeystore وواجهات النظام.
- الملف الطبي الممسوح ضوئيًا لا يصلح للتحقق من OCR من دون تثبيت التطبيق وتشغيل معالجة الصفحات؛ لا تحفظ أي قيمة مستخرجة قبل أن يراجعها المستخدم.
- سجل المواعيد والتنبيهات وسجل الجرعات والتقارير الطبية القابلة للتصدير والنسخ التلقائي وGoogle Drive ما تزال غير منفذة وظيفيًا.
- يتطلب رفع APK إلى Artifact دفع commits إلى فرع التطوير وتشغيل GitHub Actions والتحقق من نجاحه.

### إصلاحات الواجهة وPDF

- الجنس وفصيلة الدم وقرابة المرض العائلي تستخدم الآن قوائم منسدلة مثبتة على الحقول. الجنس خياران: ذكر أو أنثى؛ والقرابة تتضمن الأب والأم والإخوة والأجداد والأعمام والأخوال وأبناءهم وأفراد الأسرة الآخرين.
- يظهر العمر بالسنوات المكتملة بعد اختيار الميلاد، وفي تفاصيل الفرد وقائمة أفراد الأسرة.
- الوحدات الشائعة متاحة في قائمة داخل إضافة التحليل اليدوي ومراجعة اقتراح PDF، مع السماح بإدخال وحدة غير موجودة بالقائمة.
- نموذج Tesseract العربي أصبح موردًا مضمّنًا في APK وGradle المحلي بدل تنزيله في CI فقط. تم تثبيت بصمته ومراجعة إعدادات CI/Release للتحقق من المورد المضمّن.
- نجح `assembleDebug`, `testDebugUnitTest` (5 اختبارات)، `lintDebug`, و`assembleDebugAndroidTest`. لم يتم تشغيل اختبارات Android على محاكي أو تجربة OCR على الملف الطبي الممسوح؛ يظل فحص الإدخال الفعلي وتجربة التقرير على الجهاز مطلوبين.
